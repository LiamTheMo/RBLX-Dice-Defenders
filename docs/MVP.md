# MVP — Verdant Trial (first playable slice)

**Status:** build contract for v0.04. Numbers marked *tune* are placeholders for Studio playtests. Everything outside this file's scope is deferred (see end).

## Scope
- **Solo**, one match per server. Owner = first player whose profile loaded; if the owner leaves, the next loaded player becomes owner and the server returns to Lobby. Non-owners get `Phase = "NotOwner"` and every intent is rejected. Set place max players to 1 for production.
- **Deck:** the profile's equipped deck, exactly 5 distinct owned die types. The starter deck is C01 Pebble, C02 Needle, C03 Hammer, C04 Twinshot, C05 Longshot (stats/perks from DICE_CATALOG.md; Hammer turn speed omitted; Longshot's +25% range perk is moot under global targeting and awaits a replacement). `Start` plays the server-stored deck; the client never sends one.
- **Lobby (placeholder UI):** shown in Lobby and Ended. Sprite HUD (design 1672x941, one UIScale; borderless icons with outlined labels, inline gold/gem counters, thin XP line, copper-framed deck slots): left grid Shop/Roll/Bag/Play/Codes/Daily, Quests, gear, bottom gold/gems + XP bar (Profile) + 5-slot deck bar (Deck). Bag opens the 4-tab Bag window (every tab live from Meta + Catalog; each `BagAction` reply is toasted in the Bag): MATERIALS/ITEMS pick a quantity 1..owned on the stepper and SELL it (price from the Catalog, shown in the description) or USE it (ITEMS with a Use text); LOCK/UNLOCK toggles a stack (padlock on the card, SELL/USE off); COSMETICS EQUIP/UNEQUIP one per slot (no in-game visuals yet, LOCK off); DICE UNEQUIP ALL resets the loadout to the starter deck through `EquipDeck` (off when it already is), dice LOCK/SELL off ("Copies are kept for future level-ups"); Roll opens the Roll menu (below); Shop/Codes/Daily/gear toast "coming soon"; gems, level and XP are placeholders ("—"). Panels are centred modals; the HUD hides while one is open. Play: World 1 Trial + Start (the only way to start); Infinite shown locked. Deck: tap a slot, tap an owned die, Save. Bag DICE: owned dice (rarity, level, equipped) then the other 14 catalog dice locked; Equip picks a loadout slot and sends `EquipDeck`. Ended shows a dismissable results card (result, wave, Gold). Single place, solo: no queue, party or teleport.
- **Settings** (gear; 23 settings in `src/shared/SettingsDefs.luau`, the one registry the client draws and the server cleans against): saved in the profile (`Settings`) and loaded from the first Meta that carries them (no toast, not sent back; Roblox's own Reduced Motion still forces ours ON); later Metas never overwrite the store. Player changes collect into one patch sent by `SaveSettings` 2 s after the last change and at once when the menu closes; a send the client refuses itself (throttle, one in flight) stays pending and retries, and a server rejection drops it. Shadows, UI Scale, Reduced Motion and Show FPS take effect; the other 19 are saved but labelled "coming soon" (Auto Skip Waves is never decided by the client; the audio volumes have no sounds yet).
- **Quests** (server-only `Config/Quests.luau`, each reward a `Rewards` bundle, *tune*): S1 finish a Trial run (RunsPlayed ≥ 1) 50 Gold + 10 Gems; S2 clear wave 5 (BestWave ≥ 5) 100 + 20; S3 clear the Trial (TrialCleared) 250 + 50; D1 daily: defeat 150 enemies today 100 + 10; W1 weekly: defeat 1000 enemies this week 200 + 30; W2 weekly: finish 10 runs this week 300 + 30. One-time progress is derived from the stats only the run reward writes; the daily and W1 count server kills (deaths by damage, never breaches) of Won/Lost runs and W2 counts settled runs, added in the same run-id-gated settle as the reward. UTC day = `floor(os.time()/86400)` on the server and week = `floor((day + 3) / 7)` (starts Monday 00:00 UTC); effective day/week = `max(now-derived, stored)`, so a skewed clock never reopens a claimed day or week; the daily and weekly roll only at settle. Each quest pays once (per day for D1, per week for W1/W2).
- **Other claims** (all through `ClaimQuest` and `Rules/Claims`, rewards *tune*): **LOGIN** calendar (`Config/Daily.luau`, 7 bundles of Gold, Gems, XP Tomes, Gold Pouches, Fragments and starter die copies; Day 7 = 1000 Gold + 100 Gems + 2 XP Tomes, shown as a chest): claimable when today > `Login.LastDay`; the streak continues (`Streak % 7 + 1`) when LastDay was yesterday, else restarts at Day 1 (so Day 7 is followed by Day 1); pays `Days[streak]` and sets LastDay = today; a clock behind LastDay never pays. **Play milestones** P10, P20, P30, P40, P50, P100 (`Config/Milestones.luau`): once when BestWave ≥ wave; only waves ≤ `Balance.Waves` are Reachable, the others are never claimable but show their rewards. **Achievements** A1–A5 (`Config/Achievements.luau`, Badge = a Quest Log sprite key): progress derived from RunsPlayed, TrialCleared, `Stats.Kills`, account level and different dice owned; A2, A4 and A5 also grant a cosmetic. **Mastery**: at settle every owned die of the match deck gains Mastery Xp = waves completed; level = `Progression.Level(Xp, Progression.Mastery)`; levels 5/10/15/20 pay `Progression.Mastery.Rewards` once per owned die.
- **Roll** (server-only `Config/Roll.luau`, *tune*): one pool `Standard`, 1 roll = 100 Gems, 10 rolls = 900 Gems; rarity weights in basis points Common 4000, Rare 4500, Epic 1400, Legendary 100, Mythic 0, Secret 0 (sum 10000; nothing is drawable at 0); a rarity's dice are every `Config/Dice` entry of it, drawn uniformly; pity: the 80th roll in a row without a Legendary is one (the counter resets on any Legendary); Featured = L01, L02, L03. `Rules/Roll.Draw(pity, pool, count, rng)` is `count` single draws in a row with the counter carried through (ROLL 10 = ten single draws). `Roll.Buy` checks UnknownPool, UnknownPrice, Restricted (paid random items not allowed), Insufficient, then pays ONE `Rewards.Apply({Gems = -price, Dice = {[id] = n}})` (a new die arrives at Level 1, duplicates become copies) and, only after it landed, writes `RollPity[pool]` and `Stats.Rolls += count` with no yield between. The client sends only (pool, count); odds, prices, pity and the `Random` stay on the server. **PlayerPolicy** (`Services/PlayerPolicy.luau`) caches `PolicyService:GetPolicyInfoForPlayerAsync(player).ArePaidRandomItemsRestricted` per player (fetched in its own thread on join, pcall, 3 tries with 1 s / 2 s backoff, cleared on leave); unknown or failed = not allowed (fail closed), except in Studio where a failed lookup counts as allowed; the handler only reads the cache, and the answer re-pushes Meta. The Roll menu shows the Catalog's odds as true percentages (Bp / 100: 40 / 45 / 14 / 1 / 0 / 0%), the Catalog's prices, the pity bar `n / 80` from Meta and the featured dice (die art or the tinted roll glyph, name on the pill); ROLL 1 / ROLL 10 are on only when Meta.RollAllowed and Gems ≥ price (else "Not available in your region" / "Not enough Gems"); a `RollResult` replaces the featured dice with "YOUR ROLL" (one result centred, else the three rarest) until the menu closes and toasts "+1 Frost (new)" or "+10 dice (2 new)". EVENT shows "No event right now"; no rotation timer.
- **Board** 5×3 (cells 1..15, row-major). **Summon:** costs `10 + 10*s` MP (`s` = successful summons this match: 10, 20, 30, …); places a pip-1 die of a random deck type in a random empty cell. **Merge** `from → to`: both occupied, same type, same pip, pip ≤ 6, `from ≠ to`; `from` is cleared, `to` becomes pip+1 with a type re-rolled from the deck. Pip 7 shows as **7★**.
- **MP** (match-only currency, formerly Energy): start 100 (exactly the first 4 summons: 10+20+30+40); kill Grunt 15 / Runner 15 / Brute 25 / Boss 150; stipend `30 + 5*floor(w/10)` after each cleared wave. Income is the old Energy ×5, which keeps summon pacing on the old curve (greedy-bot sim, 30 seeds: ~9 summons by wave 3, 12 by wave 5, 19 per Trial).
- **Waves 1–10.** Count `min(45, 8 + floor(.35*(w-1)))`; spawn interval `clamp(1.6 - .007*w, .35, 1.6)` s; speed multiplier `min(1.6, 1 + .006*(w-1))`; HP `round(80 * (1 + .018*(w-1)) * typeMul * bossMul)` with Grunt 1, Runner .70, Brute 3.0 (armored), Boss 12. Composition for spawn index `i` (1-based): Brute if `w ≥ 5 and i % 5 == 0`, else Runner if `w ≥ 3 and i % 3 == 0`, else Grunt. Wave 10 spawns the **Thorn Warden** boss first, then the normal budget. Max 90 alive (spawns wait, never dropped).
- **Cadence:** first wave starts 4 s after Start; each next wave 4 s after the previous one is cleared. When the next wave is 10, `BossAt` is set at the start of that prep (4 s warning).
- **Lives** 20; breach −1, boss −5. **Lost** at lives ≤ 0. **Won** when wave 10 is cleared.
- **Combat:** dice auto-attack, and every die targets the alive enemy **closest to the exit** (greatest path distance) anywhere on the path; there is no range limit (playtest feedback). `hitDamage = max(1, floor(base * pip^0.85 * perk))`. Perks: Pebble ×1.05 vs Grunt; Hammer ×1.12 vs armored; Longshot ×0.9 vs Boss; Needle every 6th hit of that die instance +8 flat; Twinshot two shots at ×0.7 each (second goes to the next-closest-to-exit alive enemy, else the same target). Cooldown does not bank while idle; max 2 attacks per die per tick.
- **Reward** at match end (Won or Lost; not on abort), exactly once per run id, as one all-or-nothing `Rewards.Apply` bundle (*tune*): Gold `5*wavesCompleted` + 30 if won, account Xp `10*wavesCompleted` + 40 if won, Verdant Fragments `wavesCompleted` + 5 if won. Zero parts are left out (a wave-0 loss pays nothing but still counts the run); any refusal (e.g. a counter at the 1e9 cap) changes nothing. Also BestWave, RunsPlayed, TrialCleared, `Stats` (Kills, Wins), the daily and weekly counters and the deck's Mastery Xp.
- **Speeds (*tune*):** Grunt 6, Runner 9, Brute 4, Boss 3 studs/s.
- **Dice visuals:** white cube with dark type-tinted pips on the top face in standard 1–6 layouts; 7 is one large gold star; type colour also on a band around the lower sides. Selected die lifts with a yellow outline; valid merge partners get a white outline.
- **Framing:** the path hugs the board and the camera is fitted so path, board and boss clear the HUD at 1235×739, 844×390 and 667×375 (dice ≈ 65 px desktop, ≈ 34 px phone).

## Server data model
- **MatchState** `{runId, rng, deck (own copy), kills, phase="Playing"|"Ended", result, mp, summons, lives, wave, wavesCompleted, waveState="Prep"|"Active", nextWaveAt, bossAt, queue, qi, nextSpawnAt, enemies, nextEnemyId, board[1..15] = Die|false, nextDieId, lastNow, rewardGranted, out}`. Lobby = no MatchState.
- **Die** `{id, type, pip, cd, hits}`. **Enemy** `{id, kind, hp, maxHp, speed, spawnAt, dist}`; `dist = speed * (now - spawnAt)`.
- **Profile v8** `{Version=8, Gold, Gems, Xp, BestWave, RunsPlayed, TrialCleared, LastRewardRunId, Dice={[id]={Level 1..10, Copies}}, Deck={5 ids}, Claimed={[questId]=true}, Daily={Day, Kills, Claimed={[questId]=true}}, Weekly={Week, Kills, Runs, Claimed={[questId]=true}}, Stats={Kills, Wins, Rolls}, Login={Streak 0..7, LastDay}, Milestones={[id]=true}, Achievements={[id]=true}, Mastery={[dieId]={Xp, Claimed={["5"]=true}}}, Redeemed={[codeId]=true}, Materials={[id]=n}, Items={[id]=n}, Cosmetics={Owned={[id]=true}, Equipped={[slot]=id}}, Settings={[settingId]=value}, Locked={[id]=true}, RollPity={[poolId]=0..Max−1}, profileRevision, sessionLease}`; counts are integers in [0, 1e9] (Materials and Items counts ≥ 1); nil → default; bad shape → Corrupt; newer version → NewerVersion (never repaired or overwritten). New profiles start with 50 Gems; those 50 come only from `Default()` and `MIGRATIONS[3]`, so a v4 save missing Gems loads 0. Sanitising keeps only known dice (the 5 starters are always present), resets an illegal Deck to the starter deck, keeps only `true` flags for known quests of the right kind (`Claimed`: neither daily nor weekly; `Daily.Claimed`: daily; `Weekly.Claimed`: weekly) and for milestone, achievement and code ids in their configs, and keeps only `Config/Inventory` ids with positive counts (Materials, Items) or `true` flags (Cosmetics); `Mastery` keeps entries for `Config/Dice` ids, whose `Claimed` set holds only the curve's milestone levels, keyed by the level as a string (DataStores and remotes drop sparse numeric keys; a numeric key still reads as claimed); `Settings` keeps `SettingsDefs.clean(def, stored[id])` for each registry key (a missing key is its default on the client); `Locked` keeps `true` flags for `Config/Inventory` Material and Item ids; `Cosmetics.Equipped` keeps a slot only when its id is owned and that cosmetic's `Slot` is the key; `RollPity` keeps, per `Config/Roll` pool, an integer in 0..Max−1 (else 0; unknown pools dropped) and `Stats.Rolls` is a count; the flag, inventory, lock, mastery and settings walks go over the config or registry, so a huge stored table there costs nothing. `MIGRATIONS[1]` (v1→v2) keeps every v1 field and adds the defaults; `MIGRATIONS[2]` (v2→v3) keeps every v2 field and starts `Redeemed` empty; `MIGRATIONS[3]` (v3→v4) keeps every v3 field, grants the 50 starter Gems and starts Xp, Materials, Items and Cosmetics empty (stray values dropped); `MIGRATIONS[4]` (v4→v5) keeps every v4 field and starts Stats, Weekly, Login, Milestones, Achievements and Mastery empty (stray values dropped); `MIGRATIONS[5]` (v5→v6) keeps every v5 field and starts Settings empty (stray value dropped); `MIGRATIONS[6]` (v6→v7) keeps every v6 field and starts Locked and Cosmetics.Equipped empty (stray values dropped); `MIGRATIONS[7]` (v7→v8) keeps every v7 field and starts RollPity (0 per pool) and Stats.Rolls (0) empty (stray values dropped); the store writes the result back on load. Level and Copies are stored and shown but have no effect yet.

## Tick
`RunService.Heartbeat` in MatchService calls `Match.Step(state, workspace:GetServerTimeNow())` at 10 Hz, `dt` clamped to 0.25 s, inside `pcall` (error → result "Error", no reward). Order: wave advance → spawn → move + breach (lose check) → dice attacks → deaths + kill MP → wave clear / win.

**Enemy rendering:** server creates no enemy parts. Clients draw each enemy at `Layout.PositionAt(speed * (GetServerTimeNow() - spawnAt))` (exact because the MVP has no slows). HP, hits and deaths are server truth.

## Remotes (client sends intent only)
Every intent is a RemoteFunction (`InvokeServer`; no `InvokeClient` anywhere) returning `(ok: boolean, code: string?)`. Guard order: token bucket per player+remote → validator with **exact** arg count (pcall) → ready (profile loaded, sender is owner) → `seq` integer in [1, 2^31−1] and greater than the last accepted (consumed even if the rules reject) → handler (validates, then mutates, never yields, pcall).
Hard violations (RateLimited, BadArgs, BadSeq, and a client firing a server→client event) are logged (throttled) and kick at 20. Soft rejections (NotOwner, NotLoaded, WrongPhase, NoMP, BoardFull, IllegalMerge, BadDeck, UnknownDie, NotOwned, UnknownQuest, NotComplete, AlreadyClaimed, Overflow, BagAction's UnknownItem, Insufficient, Locked, NotSellable, NotUsable, Roll's UnknownPool, UnknownPrice, Restricted, and RedeemCode's Invalid, Expired, AlreadyRedeemed and its own RateLimited) are not counted.

- Client throttles each intent to ≤ 4/s and keeps a monotonically increasing `seq` shared by all intents.

## Persistence
Live store `DD_Profiles_v1`; Studio uses `DD_Profiles_v1_Studio`, or the in-memory store when Studio has no API access (in-memory is only reachable when `RunService:IsStudio()`). Key `Profile_<userId>`. 120 s lease renewed by each save; LeaseHeld waits up to 130 s; LeaseLost/StaleRevision → profile forgotten, Phase "Failed", no further writes. Saves: match end (after reward), 60 s autosave, leave (release), BindToClose (3 attempts, 25 s). Owner leaving or shutdown mid-match aborts with no reward. Load failure → no board, no rewards, nothing written.
