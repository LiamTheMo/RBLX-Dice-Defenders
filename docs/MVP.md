# MVP — Verdant Trial (first playable slice)

**Status:** build contract for v0.04. Numbers marked *tune* are placeholders for Studio playtests. Everything outside this file's scope is deferred (see end).

## Scope
- **Solo**, one match per server. Owner = first player whose profile loaded; if the owner leaves, the next loaded player becomes owner and the server returns to Lobby. Non-owners get `Phase = "NotOwner"` and every intent is rejected. Set place max players to 1 for production.
- **Deck:** the profile's equipped deck, exactly 5 distinct owned die types. The starter deck (and the only dice obtainable so far) is C01 Pebble, C02 Needle, C03 Hammer, C04 Twinshot, C05 Longshot (stats/perks from DICE_CATALOG.md; Hammer turn speed omitted; Longshot's +25% range perk is moot under global targeting and awaits a replacement). `Start` plays the server-stored deck; the client never sends one.
- **Lobby (placeholder UI):** shown in Lobby and Ended. Sprite HUD (design 1672x941, one UIScale; borderless icons with outlined labels, inline gold/gem counters, thin XP line, copper-framed deck slots): left grid Shop/Roll/Bag/Play/Codes/Daily, Quests, gear, bottom gold/gems + XP bar (Profile) + 5-slot deck bar (Deck). Bag opens the 4-tab Bag window (DICE live from the profile; MATERIALS/ITEMS/COSMETICS show client-only sample data; all buttons except Equip are disabled previews); Shop/Roll/Codes/Daily/gear toast "coming soon"; gems, level and XP are placeholders ("—"). Panels are centred modals; the HUD hides while one is open. Play: World 1 Trial + Start (the only way to start); Infinite shown locked. Deck: tap a slot, tap an owned die, Save. Bag DICE: owned dice (rarity, level, equipped) then the other 14 catalog dice locked; Equip picks a loadout slot and sends `EquipDeck`. Ended shows a dismissable results card (result, wave, Gold). Single place, solo: no queue, party or teleport.
- **Quests** (server-only `Config/Quests.luau`, each reward a `Rewards` bundle, *tune*): S1 finish a Trial run (RunsPlayed ≥ 1) 50 Gold + 10 Gems; S2 clear wave 5 (BestWave ≥ 5) 100 + 20; S3 clear the Trial (TrialCleared) 250 + 50; D1 daily: defeat 150 enemies today 100 + 10; W1 weekly: defeat 1000 enemies this week 200 + 30; W2 weekly: finish 10 runs this week 300 + 30. One-time progress is derived from the stats only the run reward writes; the daily and W1 count server kills (deaths by damage, never breaches) of Won/Lost runs and W2 counts settled runs, added in the same run-id-gated settle as the reward. UTC day = `floor(os.time()/86400)` on the server and week = `floor((day + 3) / 7)` (starts Monday 00:00 UTC); effective day/week = `max(now-derived, stored)`, so a skewed clock never reopens a claimed day or week; the daily and weekly roll only at settle. Each quest pays once (per day for D1, per week for W1/W2).
- **Other claims** (all through `ClaimQuest` and `Rules/Claims`, rewards *tune*): **LOGIN** calendar (`Config/Daily.luau`, 7 bundles of Gold, Gems, XP Tomes, Gold Pouches, Fragments and starter die copies; Day 7 = 1000 Gold + 100 Gems + 2 XP Tomes, shown as a chest): claimable when today > `Login.LastDay`; the streak continues (`Streak % 7 + 1`) when LastDay was yesterday, else restarts at Day 1 (so Day 7 is followed by Day 1); pays `Days[streak]` and sets LastDay = today; a clock behind LastDay never pays. **Play milestones** P10, P20, P30, P40, P50, P100 (`Config/Milestones.luau`): once when BestWave ≥ wave; only waves ≤ `Balance.Waves` are Reachable, the others are never claimable but show their rewards. **Achievements** A1–A5 (`Config/Achievements.luau`, Badge = a Quest Log sprite key): progress derived from RunsPlayed, TrialCleared, `Stats.Kills`, account level and different dice owned; A2, A4 and A5 also grant a cosmetic. **Mastery**: at settle every owned die of the match deck gains Mastery Xp = waves completed; level = `Progression.Level(Xp, Progression.Mastery)`; levels 5/10/15/20 pay `Progression.Mastery.Rewards` once per owned die.
- **Board** 5×3 (cells 1..15, row-major). **Summon:** costs `10 + 10*s` MP (`s` = successful summons this match: 10, 20, 30, …); places a pip-1 die of a random deck type in a random empty cell. **Merge** `from → to`: both occupied, same type, same pip, pip ≤ 6, `from ≠ to`; `from` is cleared, `to` becomes pip+1 with a type re-rolled from the deck. Pip 7 shows as **7★**.
- **MP** (match-only currency, formerly Energy): start 100 (exactly the first 4 summons: 10+20+30+40); kill Grunt 15 / Runner 15 / Brute 25 / Boss 150; stipend `30 + 5*floor(w/10)` after each cleared wave. Income is the old Energy ×5, which keeps summon pacing on the old curve (greedy-bot sim, 30 seeds: ~9 summons by wave 3, 12 by wave 5, 19 per Trial).
- **Waves 1–10.** Count `min(45, 8 + floor(.35*(w-1)))`; spawn interval `clamp(1.6 - .007*w, .35, 1.6)` s; speed multiplier `min(1.6, 1 + .006*(w-1))`; HP `round(80 * (1 + .018*(w-1)) * typeMul * bossMul)` with Grunt 1, Runner .70, Brute 3.0 (armored), Boss 12. Composition for spawn index `i` (1-based): Brute if `w ≥ 5 and i % 5 == 0`, else Runner if `w ≥ 3 and i % 3 == 0`, else Grunt. Wave 10 spawns the **Thorn Warden** boss first, then the normal budget. Max 90 alive (spawns wait, never dropped).
- **Cadence:** first wave starts 4 s after Start; each next wave 4 s after the previous one is cleared. When the next wave is 10, `BossAt` is set at the start of that prep (4 s warning).
- **Lives** 20; breach −1, boss −5. **Lost** at lives ≤ 0. **Won** when wave 10 is cleared.
- **Combat:** dice auto-attack, and every die targets the alive enemy **closest to the exit** (greatest path distance) anywhere on the path; there is no range limit (playtest feedback). `hitDamage = max(1, floor(base * pip^0.85 * perk))`. Perks: Pebble ×1.05 vs Grunt; Hammer ×1.12 vs armored; Longshot ×0.9 vs Boss; Needle every 6th hit of that die instance +8 flat; Twinshot two shots at ×0.7 each (second goes to the next-closest-to-exit alive enemy, else the same target). Cooldown does not bank while idle; max 2 attacks per die per tick.
- **Reward** at match end (Won or Lost; not on abort), exactly once per run id, as one all-or-nothing `Rewards.Apply` bundle (*tune*): Gold `5*wavesCompleted` + 30 if won, account Xp `10*wavesCompleted` + 40 if won, Verdant Fragments `wavesCompleted` + 5 if won. Zero parts are left out (a wave-0 loss pays nothing but still counts the run); any refusal (e.g. a counter at the 1e9 cap) changes nothing. Also BestWave, RunsPlayed, TrialCleared, `Stats` (Kills, Wins), the daily and weekly counters and the deck's Mastery Xp.
- **Speeds (*tune*):** Grunt 6, Runner 9, Brute 4, Boss 3 studs/s.
- **Dice visuals:** white cube with dark type-tinted pips on the top face in standard 1–6 layouts; 7 is one large gold star; type colour also on a band around the lower sides. Selected die lifts with a yellow outline; valid merge partners get a white outline.
- **Framing:** the path hugs the board and the camera is fitted so path, board and boss clear the HUD at 1235×739, 844×390 and 667×375 (dice ≈ 65 px desktop, ≈ 34 px phone).

## Server data model
- **MatchState** `{runId, rng, deck (own copy), kills, phase="Playing"|"Ended", result, mp, summons, lives, wave, wavesCompleted, waveState="Prep"|"Active", nextWaveAt, bossAt, queue, qi, nextSpawnAt, enemies, nextEnemyId, board[1..15] = Die|false, nextDieId, lastNow, rewardGranted, out}`. Lobby = no MatchState.
- **Die** `{id, type, pip, cd, hits}`. **Enemy** `{id, kind, hp, maxHp, speed, spawnAt, dist}`; `dist = speed * (now - spawnAt)`.
- **Profile v5** `{Version=5, Gold, Gems, Xp, BestWave, RunsPlayed, TrialCleared, LastRewardRunId, Dice={[id]={Level 1..10, Copies}}, Deck={5 ids}, Claimed={[questId]=true}, Daily={Day, Kills, Claimed={[questId]=true}}, Weekly={Week, Kills, Runs, Claimed={[questId]=true}}, Stats={Kills, Wins}, Login={Streak 0..7, LastDay}, Milestones={[id]=true}, Achievements={[id]=true}, Mastery={[dieId]={Xp, Claimed={["5"]=true}}}, Redeemed={[codeId]=true}, Materials={[id]=n}, Items={[id]=n}, Cosmetics={Owned={[id]=true}}, profileRevision, sessionLease}`; counts are integers in [0, 1e9] (Materials and Items counts ≥ 1); nil → default; bad shape → Corrupt; newer version → NewerVersion (never repaired or overwritten). New profiles start with 50 Gems; those 50 come only from `Default()` and `MIGRATIONS[3]`, so a v4 save missing Gems loads 0. Sanitising keeps only known dice (the 5 starters are always present), resets an illegal Deck to the starter deck, keeps only `true` flags for known quests of the right kind (`Claimed`: neither daily nor weekly; `Daily.Claimed`: daily; `Weekly.Claimed`: weekly) and for milestone, achievement and code ids in their configs, and keeps only `Config/Inventory` ids with positive counts (Materials, Items) or `true` flags (Cosmetics); `Mastery` keeps entries for `Config/Dice` ids, whose `Claimed` set holds only the curve's milestone levels, keyed by the level as a string (DataStores and remotes drop sparse numeric keys; a numeric key still reads as claimed); the flag, inventory and mastery walks go over the config, so a huge stored table there costs nothing. `MIGRATIONS[1]` (v1→v2) keeps every v1 field and adds the defaults; `MIGRATIONS[2]` (v2→v3) keeps every v2 field and starts `Redeemed` empty; `MIGRATIONS[3]` (v3→v4) keeps every v3 field, grants the 50 starter Gems and starts Xp, Materials, Items and Cosmetics empty (stray values dropped); `MIGRATIONS[4]` (v4→v5) keeps every v4 field and starts Stats, Weekly, Login, Milestones, Achievements and Mastery empty (stray values dropped); the store writes the result back on load. Level and Copies are stored and shown but have no effect yet.

## Tick
`RunService.Heartbeat` in MatchService calls `Match.Step(state, workspace:GetServerTimeNow())` at 10 Hz, `dt` clamped to 0.25 s, inside `pcall` (error → result "Error", no reward). Order: wave advance → spawn → move + breach (lose check) → dice attacks → deaths + kill MP → wave clear / win.

**Enemy rendering:** server creates no enemy parts. Clients draw each enemy at `Layout.PositionAt(speed * (GetServerTimeNow() - spawnAt))` (exact because the MVP has no slows). HP, hits and deaths are server truth.

## Remotes (client sends intent only)
Every intent is a RemoteFunction (`InvokeServer`; no `InvokeClient` anywhere) returning `(ok: boolean, code: string?)`. Guard order: token bucket per player+remote → validator with **exact** arg count (pcall) → ready (profile loaded, sender is owner) → `seq` integer in [1, 2^31−1] and greater than the last accepted (consumed even if the rules reject) → handler (validates, then mutates, never yields, pcall).
Hard violations (RateLimited, BadArgs, BadSeq, and a client firing a server→client event) are logged (throttled) and kick at 20. Soft rejections (NotOwner, NotLoaded, WrongPhase, NoMP, BoardFull, IllegalMerge, BadDeck, UnknownDie, NotOwned, UnknownQuest, NotComplete, AlreadyClaimed, Overflow, and RedeemCode's Invalid, Expired, AlreadyRedeemed and its own RateLimited) are not counted.

| Remote | Kind | Args | Rules | Rate |
|---|---|---|---|---|
| `Start` | RF | `(seq)` | owner, loaded, phase Lobby or Ended, stored deck legal (else BadDeck) | 1/s, burst 2 |
| `Summon` | RF | `(seq)` | Playing, mp ≥ cost, empty cell | 5/s, burst 8 |
| `Merge` | RF | `(seq, from 1..15, to 1..15)` | Playing, merge rules above | 5/s, burst 8 |
| `EquipDeck` | RF | `(seq, ids)`: plain array, keys exactly 1..5, distinct strings of 1–8 bytes (else BadArgs) | not Playing; every id known (UnknownDie) and owned (NotOwned) | 1/s, burst 3 |
| `ClaimQuest` | RF | `(seq, id)`: string of 1–16 bytes | any phase; one router (`Rules/Claims`) over disjoint id spaces: quest ids (S1–S3, D1, W1, W2), `LOGIN`, milestones `P10` `P20` `P30` `P40` `P50` `P100`, achievements `A1`–`A5`, mastery `<dieId>:<level>` (e.g. `C01:5`; milestone levels only, written plainly); UnknownQuest, AlreadyClaimed, NotComplete, Overflow. Each claim validates fully, then pays one `Rewards.Apply` bundle and writes its once-only flag (only after Apply succeeded) with no yield between | 2/s, burst 4 |
| `RedeemCode` | RF | `(seq, code)`: 1–32 bytes of ASCII letters, digits, `-`, `_` | any phase; trimmed + upper-cased, once per player ever (`Redeemed[Id]`), Gold (and optional Gems) as one `Rewards.Apply` bundle. Replies only Invalid (unknown, not started, or Gold or Gems cap), Expired, AlreadyRedeemed, RateLimited. Limiter per session: 5 free failures, then each failure locks 15 s doubling to 600 s (locked: RateLimited, code not evaluated, lock not extended); the 50th rejection of a session kicks | 1/s, burst 3 |
| `State` | RE S→C | snapshot below | on change, ≤ 1 per tick + 1 per intent | — |
| `Enemies` | RE S→C, owner only | batch below | ≤ 10 Hz, only when non-empty | — |
| `Catalog` | RE S→C, that player only | display catalogue below | once on load, before the first Meta | — |
| `Meta` | RE S→C, that player only | lobby payload below | on load, on any profile change, on UTC day change | — |

- **State:** `{Phase="Loading"|"Failed"|"NotOwner"|"Lobby"|"Playing"|"Ended", MP, SummonCost, Wave, Lives, NextWaveAt?, BossAt?, Result?="Won"|"Lost"|"Aborted"|"Error", RewardGold?, RewardXp?, Board={[1..15] = {T="C01", P=1} or false}, Gold, BestWave, RunsPlayed, TrialCleared}`.
- **Enemies:** `{S={{Id, Kind, SpawnAt, Speed, MaxHp, Hp}}, H={{Id, Hp}}, R={{Id, Why="Kill"|"Breach"}}, F={{Cell, Id}}}` — arrays of records only (sparse numeric keys do not survive remotes).
- **Meta:** `{Dice={{Id, Level, Copies}}, Deck={5 ids}, Quests={{Id, Name, Desc, Goal, Progress, Gold, Gems, Claimed, Daily, Section="Story"|"Daily"|"Weekly"}}, DailyResetAt, WeeklyResetAt, Login={Streak, ClaimedToday, NextClaimAt, NextDay?}, Milestones={{Id, Claimed, Claimable}}, Achievements={{Id, Progress, Claimed}}, Mastery={{Id, Level, Xp, XpGoal, Claimed={levels}}}, Gems, Xp, Level, XpInto, XpNeed, Materials={{Id, Quantity}}, Items={{Id, Quantity}}, Cosmetics={{Id}}}` (owned cosmetics; Level/XpInto/XpNeed from `Progression.Level(Xp, Progression.Account)`; Login.Streak = days of the current cycle already claimed, NextDay = the calendar day a claim now would pay, NextClaimAt = when the next claim opens; Mastery rows for owned dice, Xp into the level and XpGoal its need; Quests, Milestones and Achievements in config order, the other id arrays sorted by Id); read-only display data.
- **Catalog:** `{StarterDeck={ids}, Dice={{Id, Name, Rarity, Damage, Rate}}, Materials={{Id, Name, Rarity, Description, Sell?}}, Items={{Id, Name, Rarity, Description, Icon?, Sell?, Use?}}, Cosmetics={{Id, Name, Rarity, Type, Slot, Description}}, Daily={Days={{Day, Chest?, Rewards}}}, Milestones={{Id, Wave, Reachable, Rewards}}, Achievements={{Id, Name, Desc, Goal, Badge, Rewards}}, Mastery={Max, Need={per level 1..Max−1}, Milestones={{Lv, Rewards}}}, Repeat={PerWave=Rewards, Win=Rewards}}`; Dice, Materials, Items and Cosmetics sorted by Id, the rest in config order; Damage = die base damage, Rate = attacks/s, Use = display text such as "+100 XP"; Rewards = `Rewards.Lines`: `{{Kind="Gold"|"Gems"|"Xp"|"Material"|"Item"|"Die"|"Cosmetic", Id?, Amount}}` (counters first, then ids sorted; a cosmetic counts 1). Built once per server by `Rules/Catalog`; no redeem code data.
- Client throttles each intent to ≤ 4/s and keeps a monotonically increasing `seq` shared by all intents.

## Persistence
Live store `DD_Profiles_v1`; Studio uses `DD_Profiles_v1_Studio`, or the in-memory store when Studio has no API access (in-memory is only reachable when `RunService:IsStudio()`). Key `Profile_<userId>`. 120 s lease renewed by each save; LeaseHeld waits up to 130 s; LeaseLost/StaleRevision → profile forgotten, Phase "Failed", no further writes. Saves: match end (after reward), 60 s autosave, leave (release), BindToClose (3 attempts, 25 s). Owner leaving or shutdown mid-match aborts with no reward. Load failure → no board, no rewards, nothing written.
